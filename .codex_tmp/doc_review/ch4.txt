[P:Heading 2] 4.1 用户登录与权限控制模块实现

[P:Normal] 用户登录模块负责身份识别与角色区分。系统面向教师和学生两类用户，不同角色登录后进入不同功能界面。教师登录后进入教师工作台，可使用作业发布、学生学情查看、知识图谱维护等功能。学生登录后进入学生学习空间，可使用智能问答、作业完成、薄弱点查看和针对性训练等功能。因此，登录时需完成身份认证，后续访问过程中进行权限控制。

[P:Normal] 登录功能采用前后端分离方式实现。前端基于 Vue 3 构建登录页面，并使用 Pinia 保存当前用户状态。后端基于 FastAPI 提供登录、注册和用户信息查询接口。用户登录成功后，后端生成访问令牌并返回用户基本信息，前端根据用户角色跳转到对应页面。

[P:Normal] 用户登录与权限控制流程如图 4-1 所示。

[P:表格内容] 图4-1 用户登录与权限控制流程

[P:Normal] 具体实现过程如下。

[P:Normal] （1）用户在登录页面输入用户名和密码后，前端将表单数据提交到后端 /api/auth/login 接口。后端根据用户名查询 users 用户表，并对用户输入的密码进行校验。密码经哈希处理后存储，以保障账户信息安全。若用户不存在或密码错误，返回登录失败提示。

[P:Normal] （2）用户身份校验通过后，后端根据用户编号生成访问令牌，并将令牌、用户编号、用户名、角色和班级等信息返回给前端。前端收到返回结果后，将令牌和角色保存至会话存储，并根据角色跳转到对应页面。教师用户进入教师端首页，学生用户进入学生端首页。

[P:Normal] （3）为支持同一浏览器中教师和学生身份同时使用，登录状态保存到 sessionStorage 中，而非所有标签页共享的 localStorage。这样，每个标签页拥有独立登录状态，教师端与学生端可同时打开，互不影响，便于演示及多角色教学。

[P:Normal] （4）在后续访问过程中，前端通过 Axios 请求拦截器自动在请求头中携带访问令牌。后端收到请求后解析令牌，获取用户身份。对于教师端接口，后端会进一步判断当前用户角色是否为教师。对于前端页面跳转，路由守卫也会根据用户角色限制页面访问。通过前端路由控制与后端接口校验相结合，实现基本的角色权限隔离。

[P:Normal] 综上，用户登录与权限控制模块奠定了统一的身份认证基础。该模块清晰划分教师端与学生端功能入口，并为后续功能提供可靠的身份信息。

[P:Heading 2] 4.2 教师发布作业模块实现

[P:Normal] 教师发布作业模块连接教师教学任务与学生学习行为。教师可通过该模块创建作业，设置标题、发布时间、截止时间、发布班级及题目内容。作业题目包括选择题、填空题和编程题三类。为降低教师重复命题的工作量，作业发布模块集成大模型辅助出题功能：教师输入题目要求、相关知识点及各题型数量，系统自动生成题目初稿，教师确认或修改后发布。

[P:Normal] 该模块除创建作业内容外，还负责绑定题目与知识点。教师发布作业时可为题目绑定一个或多个知识点，系统也会根据输入的知识点、题目标题和题干自动推荐相关知识点。题目与知识点的绑定结果保存至数据库，为后续薄弱点识别提供依据。当学生提交作业后，若某题未通过，系统根据该题绑定的知识点，将其记录为学生薄弱点，形成“作业发布—学生作答—自动判题—薄弱点更新”的学习闭环。

[P:Normal] 教师发布作业流程如图 4-2 所示。

[P:表格内容] 图4-2 教师发布作业流程

[P:Normal] （1）教师进入作业发布页面后，首先填写作业的基本信息，包括作业标题、作业状态、开始时间、截止时间以及发布班级。系统根据所选班级范围确定作业接收对象，同一作业可一次性发布给班级内所有学生。若教师暂不希望学生查看，可先将作业保存为草稿，待题目和时间确认后再发布。

[P:Normal] （2）系统支持三类题型：选择题、填空题和编程题。前端根据题型动态展示不同编辑区域：选择题提供选项编辑和正确选项设置。填空题提供参考答案输入区。编程题提供初始代码、测试用例和大模型判题参数设置。教师可手动新增题目，也可从题库选择已有题目导入。题目导入后仍可修改题干、答案、解析和测试用例，使复用题目适配本次作业要求。

[P:Normal] （3）当教师选择大模型辅助出题时，系统收集出题要求、知识点及各题型数量，整理为统一指令后发送给大模型。大模型根据要求生成题目内容、参考答案和答案解析。若为编程题，同时给出测试用例。系统将生成结果转换为作业题目，追加至当前作业。教师仍可对生成题目进行二次修改，如调整题干、修改选项、增删测试用例或重新绑定知识点。大模型辅助出题提示词如表 4-1 所示。

[TABLE]
输入 | 教师填写的出题要求和题目数量
输出 | 满足教师要求的题目
提示词 | 你是一名 Java 课程作业设计助手。请根据教师要求一次生成多道作业题，支持编程题、选择题和填空题。知识点：{知识点}。教师要求：{出题要求}。数量：编程题 {编程题数量}，选择题 {选择题数量}，填空题 {填空题数量}。要求：只返回题目生成结果，不要解释。题型只能是编程题、选择题、填空题。编程题面向 Java 初学者，主类固定为 Main，并给出 2 到 4 个测试用例。选择题需要给出选项和正确答案。填空题需要给出参考答案和简短解析。

[P:Normal] （4）题目创建完成后，教师需为每道题绑定相关知识点。系统支持教师手动搜索并绑定知识点，同时根据大模型生成题目的标题、题干及教师输入的知识点，在知识图谱中检索相关节点并自动推荐绑定结果。保存作业时，系统将作业基本信息、题目信息、测试用例、发布班级及题目—知识点关联关系写入数据库。保存后，作业出现在学生端作业列表，学生可在规定时间内作答。同时，题目与知识点的绑定关系将被自动判题模块使用：当学生某题未通过时，系统根据绑定知识点将其标记为薄弱点，为后续薄弱点分析和针对性训练提供数据基础。

[P:Normal] 通过该模块，教师既可手动维护作业，也可借助大模型快速生成题目，并通过知识点绑定将作业结果与学生薄弱点识别关联。该设计降低了教师命题与维护成本，并为后续自动判题、薄弱点分析和个性化训练提供了数据基础。

[P:Heading 2] 4.3 学生完成作业模块实现

[P:Normal] 学生完成作业模块面向学生的作业查看、在线作答与提交反馈过程，支持学生在浏览器中完成从阅读题目到提交答案的完整学习流程。教师发布作业后，被分配到的学生可在学生端查看作业列表，进入详情页完成作答并提交。系统支持三类题型，其中编程题是作业模块的重点。为优化学生在网页端编写代码的体验，编程题作答区域引入 CodeMirror 代码编辑器，学生无需切换至本地环境，即可直接在浏览器中编写、修改和提交 Java 代码。学生提交编程题代码后，系统自动在后端通过 Docker 沙箱完成编译和运行，以此保证系统安全。

[P:Normal] 学生完成作业流程如图 4-3 所示。

[P:表格内容] 图4-3 学生完成作业流程

[P:Normal] （1）学生登录后进入作业列表页面，选择教师已发布且分配给自己的作业。系统根据作业编号向后端请求详情，后端校验当前学生是否有权访问，并判断作业是否已开始。校验通过后，返回作业基本信息和题目列表。

[P:Normal] （2）学生进入作答页面后，系统按题目类型展示不同作答区域。选择题以选项形式展示，填空题根据题干空白位置生成输入框，编程题进入在线代码编辑区域。编程题引入 CodeMirror 编辑器，提供 Java 代码高亮、行号显示、括号匹配、缩进、撤销重做等功能，学生可直接在网页中编写代码。

[P:Normal] （3）学生完成全部题目后点击提交，前端检查是否存在未作答题目。检查通过后，系统将每道题的作答内容统一封装提交至后端。编程题提交代码内容，选择题和填空题提交答案内容。

[P:Normal] （4）后端收到提交请求后，再次校验题目是否属于当前作业，并检查提交内容是否完整。校验通过后，系统为每道题生成提交记录，状态设为“已提交”。随后返回提交成功信息，并将提交记录交给后台自动判题模块处理。

[P:Normal] 通过上述设计，学生完成作业模块实现了从作业查看、题目切换、在线作答、草稿保存到统一提交的完整流程。其中，CodeMirror 的引入改善了编程题网页端输入体验，学生可直接在系统中完成 Java 代码编写。同时，系统在提交前后分别进行前端完整性检查和后端合法性校验，保证了作业提交数据的完整性与有效性，为后续自动判题与薄弱点更新提供了可靠的数据基础。

[P:Heading 2] 4.4 自动判题与薄弱点更新模块实现

[P:Normal] 自动判题模块是编程作业系统的核心，负责在学生提交作业后对不同类型题目判分，并将结果反馈给学生和教师。同时，该模块承担薄弱点更新功能：当学生某题未通过时，系统根据绑定知识点，将其记录为学生当前未掌握的薄弱点，为后续推荐与训练提供依据。

[P:Normal] 系统中的题目类型包括选择题、填空题和编程题。对于选择题，采用选项匹配判题，将学生所选选项与教师设置的标准答案直接比对。对于填空题等可能存在多种表述的题目，调用大模型进行语义判分。对于编程题，先在 Docker 沙箱中完成编译和测试用例运行，再结合大模型进行辅助评审，以提高判题安全性和准确性。自动判题与薄弱点更新流程如图 4-4 所示。

[P:表格内容] 图4-4 自动判题与薄弱点记录流程

[P:Normal] 具体流程如下。

[P:Normal] （1）学生提交作业后，系统首先保存提交记录，状态设为 submitted。随后通过后台任务执行自动判题，避免代码编译、程序运行及大模型调用阻塞前端页面。

[P:Normal] （2）后台判题任务根据题目类型选择不同判题方式。选择题通过选项匹配判分。填空题结合大模型进行语义判分。编程题则在 Docker 沙箱中运行，并根据测试用例进行判题。

[P:Normal] （3）对于编程题，将学生提交的 Java 代码写入临时文件，并在 Docker 容器中完成编译和运行。容器运行时关闭网络访问，设置内存、CPU 和超时限制，避免学生代码直接执行于服务器环境，提高安全性。程序运行后，将实际输出与期望输出比较，得到初步判题结果。

[P:Normal] （4）在测试用例判题基础上，进一步引入大模型辅助评审。系统将题目描述、评分标准、测试运行结果、绑定知识点和学生代码构造成提示词，要求大模型以 JSON 格式返回是否通过、问题说明和诊断信息。该方式可以弥补单纯测试用例判题的不足，减少学生“面向测试用例编程”带来的误判，也能够处理部分难以完全通过固定输入输出判断的题目。大模型辅助评审提示词如下表4-2。

[P:图和表格介绍文本] 表4-2 大模型辅助评审提示词

[TABLE]
输入 | 题目信息、评分标准、判题方式、测试用例、运行结果、知识点、学生代码
输出 | 结构化判题结果，包括是否通过、结果说明、存在问题、代码优点以及诊断信息
提示词 | 你是一名严格但克制的 Java 编程作业评审助手。请根据教师给出的评分标准，对学生代码进行保守评审。作业标题：{作业标题}。题目标题：{题目标题}。题目描述：{题目描述}。是否启用测试用例：{是否启用测试用例}。判题方式：{判题方式}。教师评分标准：{教师评分标准}。题目绑定知识点：{题目绑定知识点}。测试或编译结果：{测试运行结果}。学生代码：{学生代码}。要求：只返回 JSON 格式数据，不要输出额外解释。decision 只能为 accepted 或 ai_rejected。不确定时返回 ai_rejected。需要给出 summary、issues、strengths 和 diagnoses 字段，分别表示判题总结、存在问题、代码优点和可能涉及的知识点诊断。

[P:Normal] 通过上述提示词约束，大模型可围绕题目要求、测试结果和评分标准进行结构化评审，避免返回自由文本导致后端难以解析。

[P:Normal] （5）系统综合规则判题、沙箱运行结果和大模型评审结果，生成最终判题状态，并将状态、测试结果和评审内容写入提交记录。若最终状态为 accepted，则该题通过，不更新薄弱点。否则查询该题绑定的知识点，标记为该学生未掌握的薄弱点，为后续推荐与训练提供依据。

[P:Normal] 综上，自动判题模块不仅实现了作业提交后的自动评分，还通过 Docker 沙箱提高编程题运行安全性，通过大模型辅助评审弥补单纯测试用例判题的不足，并通过题目知识点绑定机制将错题结果转化为学生薄弱点。该模块连接作业系统、知识图谱和个性化训练功能，是实现自适应辅导闭环的重要基础。

[P:Heading 2] 4.5 大模型答疑模块实现

[P:Normal] 学生在完成编程作业和复习知识点过程中，常遇到语法理解、程序报错、算法思路不清等问题。传统作业系统通常只提供固定解析，难以针对学生当前问题进行辅导。为提高交互性和智能化程度，本文设计并实现了基于大模型的学生答疑模块。学生可在聊天页面直接输入问题，系统调用大模型生成答复，并在答疑完成后异步抽取本轮对话涉及的知识点，记录为学生提问过的知识点，为学生学习轨迹回看和教师端提问热点统计提供数据支持。

[P:Normal] 学生大模型答疑流程如图 4-5 所示。

[P:表格内容] 图4-5 学生大模型答疑流程图

[P:Normal] 具体实现过程如下。

[P:Normal] （1）学生在聊天页面输入问题后，前端将问题提交至后端。后端先校验用户身份和会话归属，确认会话属于当前学生后，将问题保存至数据库，形成学生消息记录。

[P:Normal] （2）后端结合当前问题与历史对话上下文构造提示词，调用大模型生成答疑内容。提示词将大模型设定为面向学生的 Java 编程作业辅导老师，要求使用中文回答，优先帮助学生理解概念、定位错误和形成调试思路，同时避免直接代替学生完成整份作业。为提升交互体验，系统采用流式响应方式返回答复，前端实时展示生成结果。大模型辅导提示词如下表4-3所示。

[P:表格内容] 表4-3 大模型答疑提示词

[TABLE]
输入 | 学生当前问题、当前会话历史对话内容
输出 | 面向学生的自然语言答疑结果，包括问题原因解释、相关知识点说明、调试思路或学习建议
提示词 | 你是一位面向学生的 Java 辅导老师。请直接回答学生当前问题，优先帮助学生理解概念和定位错误。学生当前问题：{学生当前问题}。历史对话内容：{历史对话内容}。要求：使用中文，语气耐心、清晰。不要编造系统中没有提供的事实。可以给出简短 Java 示例，但不要替学生完成整份作业。先回答核心原因，再给出可执行的检查步骤。

[P:Normal] （3）答疑完成后，系统将大模型完整回答保存为助教消息，与学生问题共同组成一轮完整问答。为避免知识点抽取影响学生继续提问，系统在回答保存后启动后台异步任务，抽取本轮对话涉及的知识点。这样既保证答疑响应速度，又能持续积累学生提问数据。

[P:Normal] （4）知识点抽取时，系统将本轮学生问题、大模型回答、上一轮上下文及知识图谱中的已有节点列表构造成提示词。提示词要求大模型只从已有知识图谱节点中选择相关知识点，不允许生成新节点，并规定返回结果必须为 JSON 数组，每个元素包含 node_id 和 node_name。如果本轮对话没有明确涉及已有知识点，则返回空数组。大模型知识点抽取提示词如下表4-4所示。

输入 | 上一轮对话上下文、本轮学生提问、本轮大模型回答、系统知识图谱节点列表
输出 | 结构化知识点抽取结果，包括知识点编号和知识点名称
提示词 | 你是 Java 辅导系统的知识点抽取器。请根据本轮学生提问和助教回答，抽取学生实际提问到的 Java 知识点。上一轮上下文：{上一轮上下文}。学生提问：{学生提问}。助教回答：{助教回答}。知识图谱节点列表：{知识图谱节点列表}。要求：只输出 JSON 数组，不要输出 Markdown 或额外解释。最多返回 5 个知识点。只能从给定的知识图谱节点列表中选择，不允许创造新的知识点。每个元素必须包含 node_id 和 node_name，且 node_id 和 node_name 必须来自知识图谱节点列表。如果没有合适的知识点，则返回空数组。

[P:Normal] 大模型返回候选知识点后，系统根据编号在数据库中匹配记录，并对同一轮对话中的重复知识点去重，最后写入学生提问知识点记录表。需要说明的是，本模块记录“学生提问过的知识点”，并不直接将其标记为薄弱点。学生提问某个知识点只能说明其近期关注或存在疑问，是否真正属于薄弱点还需结合后续作业与训练结果判断。因此，系统将提问知识点记录与薄弱点记录分开存储，既避免误判学生掌握情况，也为教师端查看提问热点提供数据依据。

[P:Normal] 综上，大模型答疑模块实现从学生提问、模型答复、对话保存到知识点抽取的完整流程。该模块一方面提升学生编程学习中的即时反馈体验，另一方面为薄弱点推荐、教师学情分析和知识图谱应用提供持续积累的数据基础。

[P:Heading 2] 4.6 薄弱点推荐与针对性训练模块实现

[P:Normal] 薄弱点推荐与针对性训练模块帮助学生查看当前未掌握的知识点，并根据知识图谱生成针对性学习路径。学生在完成作业过程中产生的薄弱知识点在该页面集中展示。薄弱点表示学生当前需重点补齐的内容。

[P:Normal] 薄弱点推荐与针对性训练流程如图4-6所示。

[P:表格内容] 图4-6 薄弱点推荐与针对性训练流程图

[P:Normal] 具体实现过程如下：

[P:Normal] （1）学生进入薄弱点页面后，系统加载当前待掌握薄弱点和历史薄弱点。页面左侧展示待掌握薄弱点列表，学生可选择某个薄弱点查看对应知识图谱推荐结果。

[P:Normal] （2）学生选择薄弱点后，后端根据该知识点在知识图谱中的关系进行查询。系统优先查找与当前薄弱点存在依赖关系的相邻节点。若直接相关节点不足，再根据知识点名称和描述进行补充匹配。查询完成后，结合学生已有的掌握状态，对相关节点分类展示（如薄弱、推荐学习、已掌握）。这样学生不仅能看到当前薄弱点，也能看到相关前置或补充知识。

[P:Normal] 为提升页面切换体验，前端在加载当前薄弱点图谱后，对其他薄弱点对应的图谱数据进行缓存和预加载。当学生切换不同薄弱点时，若本地已有缓存数据，则直接展示，减少重复请求带来的等待时间。

[P:Normal] （3）学生点击图谱中的推荐知识点后，系统进入针对性训练流程。后端根据该知识点的名称、描述及相关概念构建提示词，要求大模型生成一道难度适中的选择题或简答题。提示词限制题目必须围绕当前知识点展开、考查核心概念，且只返回题目内容，不给出答案。

[P:Normal] （4）学生提交答案后，系统再次调用大模型判题。判题提示词包含知识点信息、题目内容和学生答案，要求大模型判断回答是否正确并给出简短反馈。若学生回答正确，系统将该知识点标记为已掌握。当前薄弱点相关的训练内容完成后，薄弱点状态更新为已掌握，并进入历史薄弱点记录。

[P:Normal] 通过该模块，系统将薄弱点识别、知识图谱推荐和大模型训练题生成结合，实现从“发现问题”到“针对训练”再到“掌握更新”的学习闭环。相比只展示错题或薄弱点列表的方式，该模块能进一步引导学生理解薄弱点之间的关联，提高复习和训练的针对性。

[P:Heading 2] 4.7 教师学情分析与人工复核模块实现

[P:Normal] 教师端学情分析模块帮助教师从班级整体和学生个体两个层面掌握学习情况。系统统计学生薄弱知识点、提问知识点及作业提交情况，为教师提供教学反馈。同时，考虑到自动判题和大模型判题可能存在误判，系统提供人工复核功能，使教师能结合学生提交代码、测试结果和大模型判定结果进行二次确认。

[P:Normal] 该模块包括数据看板、学生知识画像、作业完成情况查看和人工复核四个部分，整体流程如图 4-7 所示。

[P:表格内容] 图4-7 学情分析与人工复核流程图

[P:Normal] 教师进入系统后，可通过数据看板查看班级整体学习情况。数据看板展示学生总数、当前未掌握薄弱点数量、最近一次作业未提交学生数量等信息。薄弱点热点排行根据学生未掌握知识点的出现次数统计，反映班级共性薄弱内容。班级提问热点排行根据学生在大模型答疑中被抽取的知识点统计，反映学生近期关注较多的知识内容。

[P:Normal] 在学生知识画像部分，系统统计每名学生当前的薄弱点数量和未完成作业数量。教师可通过姓名搜索、班级筛选和排序功能快速定位学生。选择某一名学生后，系统展示该学生当前未掌握的薄弱知识点和最近提问过的知识点。薄弱知识点来源于学生作业错题，提问知识点来源于学生与大模型对话后的后台知识点抽取结果。

[P:Normal] 作业完成情况页面用于展示某次作业学生的提交状态。系统根据作业、学生和题目统计学生是否提交、已提交题目数量、最近提交时间及是否逾期等信息。教师点击学生提交记录后，可查看提交代码、测试用例执行结果、运行时间、提交次数及大模型判定结果。对于编程题，系统还保留学生的多次提交记录，便于教师了解学生修改过程。

[P:Normal] 人工复核功能用于处理自动判题结果可能存在错误的情况。系统在提交详情中展示测试结果和大模型判定信息，包括判定结果、问题总结、风险点和相关诊断内容。教师查看后，可根据实际情况选择标记通过或未通过，并填写复核备注。后端收到复核请求后，更新该次提交的最终状态，同时记录复核教师、复核时间和复核说明。

[P:Normal] 通过该模块，教师能从整体排行、个人画像和作业详情三个层面了解学生学习情况。薄弱点排行和提问热点排行帮助教师发现班级共性问题，学生知识画像帮助教师定位个体差异，人工复核机制则提高了最终判题结果的准确性。

[P:Heading 2] 4.8 知识图谱维护模块实现

[P:Normal] 知识图谱是知识点关联、薄弱点推荐、作业知识点绑定和学习情况分析的重要基础。为保证知识图谱能根据课程内容持续更新，系统在教师端提供了知识图谱维护模块。教师可在该模块中查看图谱结构，并对知识点节点及其关系进行增、删、改、查操作。同时，系统提供大模型辅助生成节点描述功能，教师输入知识点名称，系统自动生成适合教学场景的知识点说明。

[P:Normal] 本系统的知识图谱数据主要存储在 Neo4j 中，Neo4j 作为图谱数据源，保存知识点节点及其依赖关系。MySQL 中的知识点表仅保存知识点引用信息，用于作业题目绑定、薄弱点记录和章节筛选等业务场景。教师在图谱维护页面新增或修改节点后，系统更新 Neo4j 中的图谱数据，并同步维护 MySQL 中的知识点引用信息。

[P:Normal] 知识图谱维护流程如图4-8所示。

[P:表格内容] 图4-8 知识图谱维护流程图

[P:Normal] 具体实现过程如下。

[P:Normal] （1）知识图谱查询与展示。教师进入知识图谱管理页面后，前端向后端请求当前知识图谱数据。后端从 Neo4j 中查询 Knowledge 类型节点，获取节点名称、描述、章节标签和节点类型等信息，并进一步查询这些节点之间的关系。前端接收到数据后，通过图谱画布组件进行可视化展示。系统还支持按知识点名称、描述和章节标签搜索，方便教师快速定位需维护的知识点。

[P:Normal] （2）知识点节点维护。教师可新增知识点节点，也可点击已有节点后修改其名称、描述和章节标签。新增节点时，系统先判断 Neo4j 中是否存在同名知识点，若已存在则返回提示，避免重复创建。若不存在，则在 Neo4j 中创建新的 Knowledge 节点。由于作业绑定和薄弱点记录需要引用知识点，系统还会同步更新 MySQL 中的知识点记录。

[P:Normal] （3）知识点关系维护。教师可为两个知识点建立关系，表示知识点之间的依赖或关联。系统在创建关系时校验起点和终点，并对关系名称进行规范化处理，通过 Neo4j 的 MERGE 操作避免重复创建相同关系。若教师输入的起点或终点知识点尚不存在，系统会自动创建对应节点，并尝试为其生成描述。

[P:Normal] （4）大模型辅助生成知识点描述。为减少教师手动编写知识点说明的工作量，系统提供“大模型生成描述”功能。教师输入知识点名称后，后端构建提示词并调用大模型生成描述。提示词要求模型以“Java教学知识图谱编辑助手”的身份，根据知识点名称生成1到2句中文描述，重点说明该知识点是什么以及通常用于解决什么问题，并限制其不要输出标题、列表或引号。大模型返回结果后，前端将生成内容填入描述输入框，教师可继续修改并最终保存。这样既降低图谱维护成本，也保留教师对知识点内容的审核权。大模型辅助生成知识点描述提示词如下表4-5所示。

[P:图和表格介绍文本] 表4-5 大模型辅助生成知识点描述提示词

[TABLE]
输入 | 知识点名称
输出 | 知识点描述文本，用于补充知识图谱节点的描述字段
提示词 | 你是一名Java教学知识图谱编辑助手。请根据知识点名称生成一段简洁、准确、适合教学管理页展示的描述。知识点名称：{知识点名称}要求： 1. 用中文输出。 2. 1到2句话，控制在40到90字。 3. 优先解释“这是什么”和“它通常用来解决什么问题”。 4. 不要使用列表，不要输出标题，不要加引号。

[P:Normal] 综上，知识图谱维护模块实现教师对知识点节点和关系的可视化管理，并通过大模型辅助补全知识点描述。该模块为学生端薄弱点推荐、针对性训练、作业知识点绑定和教师端学情分析提供基础数据支持。
